# 用户画像与保守推荐

在「我 → 用户画像」填写学历、入学年份、学院专业和自然语言偏好。身份事实需勾选「已确认」才参与匹配；兴趣无需预设标签。年级按北京时间、九月开始的学年从入学年份计算，特殊修读情况可自行更正。

画像保存在现有数据目录的 `user-profile.json`，推荐缓存为 `notice-recommendations.json`。Windows 网页版默认目录为 `%LOCALAPPDATA%\PigeonPal\data`；桌面版使用自身的 data 目录。普通原文仍在 `crawler-state.json`，不会因推荐而删除。

## 获取与修改画像

- 可以在设置页编辑、确认和清空画像；并发编辑使用画像版本检查，冲突时重新读取，不覆盖另一处修改。
- 可以直接对小浙说「我是本科生」「我是2026级」「我希望多看有志愿时长的活动」。模型只有在本轮用户直接陈述且能引用对应原话时才能保存，成功后会回复。引用通知、历史、他人陈述和问题不授权画像更新。
- 可选学号输入按用户提供的 `3YY` 规则仅在本机推测入学年份，未确认前不用于过滤。它不推断学历，不读取已有校园认证账号，也不保存或向模型发送完整学号。纯「我的学号是……」聊天同样由本机处理，聊天消息在写入界面记录前会对匹配格式的完整学号脱敏。
- 兴趣和暂不关注各最多12条，每条120字；暂不关注只降低优先级，不会仅凭兴趣不符屏蔽通知。
- 清空会清空主文件及画像备份，通知、校园绑定和手动提醒保留。损坏画像不会被静默覆盖；可只读查看有效备份，或者明确清空重建。

## 判断与投递

通知只分「推荐」「可能相关」「明确不适用」。可能有用、资料缺失或无法确定的均保留。

首次通知整理可在同一次模型请求中生成摘要、客观资格和画像匹配结果。只有用户已确认的学历或明确入学年份，与完整、排他且有逐字正文证据的条件冲突，程序复核通过后，才能停止主动推送。学院发布单位、成绩未知、兴趣不符、优先条件、例外、时间范围歧义、关键条件在未读附件等均不据此排除；同篇包含多个机会时不能只看其中一项不匹配就排除整篇。

界面默认「推荐」保留推荐和不确定项，「全部通知」可查看本地已采集的元信息和原文详情。详情展示判断理由和原文依据；「仍然推荐」可以覆盖自动排除，「恢复自动判断」撤销覆盖。推荐优先级只影响推荐列表顺序。

新到通知在配置了自动模型处理时，最多等待180秒完成整理和匹配；原文与列表始终可见。无 Key、关闭自动处理、失败或超时后放行。主动聊天消息、网页/桌面系统通知、自动截止提醒统一遵守结果；已有自动提醒在派送前再次核对，暂缓时稍后复核，明确排除时取消。用户手动设置的提醒不受画像过滤影响。修改画像、清空或手动保留后，自动提醒可按仍有效的截止时间恢复。

原文分析缓存不含画像版本；推荐缓存单独绑定画像版本、通知指纹与策略版本。画像变化时旧排除立即失效，只重做推荐评估；有客观资格缓存时不重发长篇正文。匹配失败有限次退避，不能无限重试产生模型费用。

## 隐私与接口

画像存在本地。启用模型会把已确认学历、入学年份、学院专业和偏好等必要字段发送给用户配置的模型服务，不包含学号、校园凭据、Cookie、完整聊天或画像存储元数据。学在浙大作业保持本机处理，不参与这条模型推荐管线。

本机接口沿用 loopback、来源检查和 CSRF token：

- `GET /api/user-profile`：画像及版本；`POST /api/user-profile`：部分更新，支持 `expectedVersion`。
- `POST /api/user-profile/reset`：明确清空；`POST /api/recommendations/override`：`{noticeId, decision: "keep" | "auto"}`。
- 通知列表和详情新增 `recommendation`，包含三态判断、允许推送、暂缓、优先级、理由、证据、画像版本和手动覆盖。全部通知接口不因匹配而删项。
- 系统通知候选增加 `deferPush`，提醒接口增加 `notifyEligible`，暂缓不会被消费为已通知。

当前验证使用合成画像、通知和模拟模型响应，覆盖真实本机存储、API、缓存与提醒流程。实际模型的语义准确率需在用户填写画像并配置模型后，用真实通知继续核对；不宣称零误判。

集成复核（2026-10-20）：否定、假设与问句不授权清空画像；跨句、不同资格维度无法证明属于同一机会时保留通知；推送前暂缓的通知和提醒不记为已通知，后续可重试。
