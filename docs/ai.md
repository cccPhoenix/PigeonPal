# DeepSeek 对话、通知整理与提醒

本次实现接入 DeepSeek，使用标准库 HTTP 客户端，不增加模型 SDK 依赖。多 API 配置管理已由用户在本机验证；开发阶段通过 14 项配置管理离线检查、7 项凭据存储检查、语法检查及假数据界面检查，未执行完整自动回归或真实模型调用。
新增公开来源沿用已有模型配置，不改变开关或密钥。

## 启动和配置

先在原服务终端按 Ctrl+C 停止旧进程，再在项目根目录的 PowerShell 执行：

```powershell
python -m pip install -r requirements.txt
python scripts/serve.py
```

打开 `http://127.0.0.1:4174/`，点击左下角头像 → **API 设置**。

1. 切换到 **添加 API**，填写配置名称和 DeepSeek API key。Key 不回显到查询接口，也不写入浏览器 localStorage。
2. 基础地址默认 `https://api.deepseek.com`。若使用带 `/v1` 的地址也可，不要填写完整 `/chat/completions` 路径。
3. 模型默认 `deepseek-flash`（依据 [DeepSeek 当前模型说明](https://api-docs.deepseek.com/quick_start/pricing/)）；可以改为账号可用的模型 ID。
4. 点击「添加 API」后，自动回到 **已添加 API** 列表，显示明确的成功提示，并突出标记刚添加的配置。首份配置自动设为当前使用；后续新增不改变当前选择。
5. 在列表点击「使用此配置」切换。每份配置均可单独「验证连接」，读取模型列表验证 key 和模型名，不生成聊天回复，也不切换当前配置。
6. ITC 仍需在「身份认证」绑定校园账号；API 配置和校园绑定相互独立。

“已添加 API”和“添加 API”是同一设置弹窗中的两个独立页签。列表展示名称、模型、地址、脱敏 Key 标识、连接验证状态和当前使用标记；最多保存 20 份配置。Key 较长时只展示末尾四位用于辨认，不提供完整密钥回显。保存成功表示配置已落盘，连接是否可用需单独验证。

列表中可以编辑、验证或删除单份配置。编辑时 Key 留空保留原值；更换 Key、模型或地址会清除旧的验证状态。删除当前使用项会暂停 AI，保留其他已添加项，直到手动重新选择；清除全部配置也只影响 API，不影响校园绑定及已保存的通知、提醒。删除前在弹窗内确认。

已有的单 Key 配置会自动显示为“原有 DeepSeek 配置”，仍保持启用；下次修改时写入新的加密配置格式，无需重新填写 Key。未启用配置的添加、编辑或验证不会打断正在进行的对话。

“已添加 API”下方的 **自动处理与隐私** 提供三个全局开关：自动整理通知、允许 ITC 正文交给 DeepSeek、自动设置通知 DDL 提醒；它们不随 Key 切换而改变。当前需求允许处理 ITC，默认开启。关闭后不启动新的 ITC 整理，已发送的上游请求无法撤回，但切换当前配置后不采用旧请求的结果。配置和偏好保存即时生效，无需重启。

## 实际流程

```text
已有爬虫 → crawler-state.json → 独立 AI 工作线程
                                  ↓
                           结构化整理与校验
                                  ↓
                            notice-ai.json
                                  ↓
                       本机通知 API → 对应来源频道
                                  ↓
                         DDL → 本机提醒调度
```

- 云峰、丹阳青溪、蓝田、ITC、求是学院、本科生院均按每 300 秒检查、同主机请求间隔 15–30 秒采集。模型调用不阻塞爬虫线程；配置错误不阻止原文采集。
- 当前主界面使用上述六个通知来源及学在浙大作业频道，不再生成三个虚构频道的演示通知；新增公开来源沿用已保存的模型设置。
- 正文未补齐时可以显示原站通知。整理完成后更新原消息，不再追加一份重复摘要。
- 跨站和直接附件等仅链接条目不具备正文，不交给自动通知整理；完整正文才显示「重新整理」操作。
- 缓存由通知正文、版本、模型、地址和提示词版本共同标识。重复轮询不会反复请求模型；正文修改或模型切换会重新整理。
- 同一版本重新整理失败时缓存保留此前结果，频道与详情只展示真实失败状态；正文／模型／提示词版本改变时不会误用旧版结果。
- 模型超时、网络错误和限流采用退避；无效 key 暂停自动调用，重新保存配置后恢复。非法结果保留失败状态，可以在通知详情点「重新整理」。
- 提醒保存暂时失败时，本机线程会重试已整理通知的 DDL，不需要再次请求模型。
- 附件仅保留名称与链接，不读取附件内容。模型输入只包含通知白名单字段，清除常见联系方式和认证标记；不读取校园凭据或 Cookie。

整理使用 `notice-v3-decision` 提示词，在原有字段上增加 `noticeType`、`participation`、`benefits`、`eventTime`、`deadlineText`。频道主消息与详情共用「类型｜参与性质、面向、要点、时间、截止、收益」结构；原标题在频道折叠保留，详情仍提供完整网页正文、附件链接和原网页入口。实际到场时间和报名／申请／提交截止分开，收益必须保留获得条件。

`eventTime` 和 `deadlineText` 按原文精度展示，没有年份时也可保留“10月20日”；不补年份或时刻。已有 `eventAt`、`eventEnd`、`deadlineAt` 继续服务提醒，仅接受确定的完整日期或带时区时刻。通知的「提醒我」仍支持自定义时间。旧缓存按旧契约读取，新模型返回必须符合完整新契约；提示词版本进入缓存指纹，自动整理开启时旧结果仅重新处理一次。结构校验不能保证模型语义完全正确，原文始终可核对。字段及本次验证结果见 [通知决策摘要](notice-decisions.md)。

## 对话

聊天请求携带当前频道最近的有限上下文和称呼，不上传整个 localStorage。后端注入真实当前时间和已有提醒；询问 ITC／校园通知时，提供本机通知资料，并允许进一步检索、读取正文。

DeepSeek 可以使用六个受控工具：检索通知、读取单篇通知、检索提醒、创建提醒、修改提醒、保存称呼。不能访问任意新网址、读取认证文件、执行系统命令或下载附件。提醒／称呼工具成功后才确认结果；时间不明确应追问。请求 ID、操作 ID 和本机回执防止重复请求重复创建同一个提醒。

可以这样体验：

- 「我叫 Qyx，以后这么叫我。」
- 「请整理最近的 ITC 通知，按重要事项和截止时间列出来。」
- 「这条通知具体要求我做什么？」（先引用一条真实通知）
- 「一分钟后提醒我喝水。」
- 「把喝水提醒推迟十分钟。」
- 「取消喝水提醒。」

尚未填写 key 时会提示配置，不使用固定问答或演示回复兜底。首次开场白和界面操作确认仍属于 UI 文案。

## 提醒规则与运行条件

提醒保存在 `runtime-state.json`，由本机服务每秒检查。完成／取消后不再触发，改时间重新挂起；交付事件持久化，每次只记录一次。旧浏览器提醒在首次连接时按 ID 导入，不覆盖已存在的服务端记录。

通知 DDL 的默认策略：

- 有明确时间：优先提前 24 小时；不足 24 小时则提前 1 小时，再不足则尽快提醒。
- 只有截止日期：在截止当天 09:00 提醒；当天 09:00 已过去则尽快提醒。此时间是提醒规则，绝不是对原文截止时间的补全。
- 已过期、日期缺失或正文未补齐：不创建自动 DDL 提醒。
- 同一通知已有用户设置的有效提醒时，保留用户设置。用户完成或取消自动提醒后，不因重复轮询重新建立。
- 用户手动修改自动提醒的时间或标题后，按个人提醒保留，不再被公告更新覆盖。正文改版后不再包含未来 DDL 时，会取消相应自动提醒；正文再次明确未来 DDL 时可恢复这种由公告更新取消的提醒。

**网页版必须保持 `python scripts/serve.py` 进程运行；桌面版会自动启动并管理本机后端，无需手动运行此命令。** 关闭浏览器后服务仍记录到点事件，重新打开页面会补收；停止服务或关闭电脑后无法实时触发，重启时补收仍未交付的过期提醒。网页版在后台且已授权浏览器通知时可弹出系统通知；Electron 桌面版由主进程使用原生系统通知，关窗后仍可在托盘后台抓取与提醒。开机自动启动尚未实现。安静时段／静音只关闭打扰，消息仍保留。

## 文件和接口

通知目录新增 `notice-ai.json`（处理缓存）和 `runtime-state.json`（提醒、交付事件及近期聊天回执），两者原子写入并保留 `.bak`。原有 `crawler-state.json` 不改变 schema，独立爬虫的状态和导出命令继续可用。

API 配置复用项目已有的加密凭据容器，单独保存在认证目录的 `ai/` 子目录；默认 `~/.pigeonpal/auth/ai/`。其中 `.env` 为加密配置、`.auth-key` 为本机解密密钥，与校园绑定的两个文件分开。迁移 API 配置需单独复制该子目录。通知导出不会包含任何认证文件。持有密文和解密密钥的人仍可解密，与原有校园绑定采用相同的本机存储边界。

接口及请求约定见 [interfaces.md](interfaces.md)。供应商协议依据 [DeepSeek Chat Completion](https://api-docs.deepseek.com/api/create-chat-completion)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 和 [Tool Calls](https://api-docs.deepseek.com/guides/tool_calls)。当前使用 [非思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)，通过受控工具完成通知查询及提醒操作。

## 本机验收清单

1. API 菜单和弹窗：旧 Key 自动出现在列表；添加两份不同配置，确认成功提示、列表高亮及当前使用标记；切换／编辑（留空保留 Key）／独立验证／删除与清除；重启服务后列表和选择保持，查询接口不返回完整 Key。未验证的保存结果不能标为连接成功。
2. 连贯聊天：连续追问、切换频道、修改称呼；无 key 或无效 key 时提示真实错误。
3. ITC：先确认认证与采集状态；在 ITC 频道查看真实通知，核对摘要、正文与原链接；聊天询问 ITC 能查询本机数据。
4. 主动通知：保持运行，等待采集到新通知或原文版本更新；确认进入对应频道、有未读状态；刷新不会重复追加同一通知。
5. 闹钟：设一分钟后提醒，随后完成／稍后／取消／修改；没有具体时间的请求应追问，不能宣称已创建。
6. 后台补收：保持 Python 服务运行、关闭页面，提醒到点后重新打开；确认只收到一次并保留正确状态。
7. 自动 DDL：选择正文确有未来截止日期的通知，核对提取结果和提醒时间；取消后重启或重试整理不应重新生成。
8. 开关与故障：关闭 ITC 处理、通知静音和安静时段；暂时断网再恢复；模型故障不能中断学校采集。

以上是待用户执行的清单，不是本次已通过的测试结果。
