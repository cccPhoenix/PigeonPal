# 通知决策摘要

基础为 `origin/main` 的 `a2a31be`（最新多 API 配置），合入 `2c1243f` 的四来源功能：云峰、ITC、求是学院、本科生院。继续使用原爬虫、DeepSeek 客户端、后台工作线程、本机 JSON 存储、提醒与界面组件。

## 提取及展示契约

| 字段 | 用途 |
| --- | --- |
| `noticeType` | 新闻、评奖评优、资助、文体活动、考试报名、公示、讲座、教学教务、志愿服务、其他 |
| `participation` | 自愿参加／要求参加／仅供知悉／原文未明确 |
| `audience` | 受众及重要条件；未知为“原文未说明” |
| `summary` | 最多 160 字的一句话要点，去掉公文标题套话 |
| `eventTime` | 实际到场起止时间，保留原文精度；不估算时间投入 |
| `deadlineText` | 按动作、对象分别标注报名／申请／提交截止 |
| `location` | 已明确地点，否则 null |
| `benefits` | 明确的实际收益及获得条件，未知或不涉及使用规定文案 |

保留内部 `category`、精确时间字段、`todos` 与 `notes`，以兼容既有提醒。模型请求只含系统规则和作为数据的通知 JSON，没有工具；正文指令不得执行，附件名称不能作为附件事实来源。状态不是 ready 时不把旧结果当作新的整理结果。

## 缓存与去重

提示词升级至 `notice-v3-decision`。新模型响应严格校验所有字段，缓存读取单独兼容旧契约，不修改爬虫 JSON 的 schemaVersion。旧结果保持可读，指纹失配后按原自动整理开关重新处理；同指纹的成功结果在轮询、重启后复用，非法结果保持失败、不无限调用。来源、通知 ID 和消息 ID 保持不变。

浏览器持久化保留新字段，旧消息缺字段时显示“旧版整理结果待更新”。API 的消息 revision 纳入整理状态及错误，使正在整理／失败状态能原位更新；不会追加第二条通知。无 key 保留“没有配置api-key，数据整理暂不可用”。

| --- | --- |
