# 学在浙大作业

启动 `python scripts/serve.py` 后，侧栏有「学在浙大·作业」频道。使用「我 → 身份认证」里已有的校园绑定；未绑定时等待认证。校园账号校验仍只负责 ZJUAM，作业采集另外建立学在浙大的站点会话。

## 保存位置与内容

继续使用原有数据目录的 `crawler-state.json`，来源 ID 为 `xzzd`、任务 ID 为 `xzzd:<activityId>`，不需要数据库。Windows 默认路径为 `%LOCALAPPDATA%\PigeonPal\data\crawler-state.json`；自定义 `--data-dir`、迁移和导出方式与其他来源相同。

每条任务保存标题、课程名称/编号、开放和截止时间、提交状态、是否关闭、任务描述及题目附件链接。`homework` 元数据固定为 `activityId`、`courseId`、`courseName`、`courseCode`、`openAt`、`deadlineAt`、`submissionStatus`、`isClosed` 八项。没有提供的时间或状态保持未知，不把「已关闭」当成「已提交」，不因任务从待办消失而推断完成。没有描述的任务仍能保存并展示，不伪造正文。

任务与正文使用哈希和版本去重；截止时间、提交状态变化会更新同一张消息卡片。轮转进度保存在同一 JSON 的 `collectors.xzzd` 中，重启继续处理。存储仅保留清洗后的白名单，不保存原始接口响应、票据、Cookie 或认证 HTML。

## 请求与范围

- 首次采集或等待认证后的作业来源优先于普通通知来源排队；已有采集正在执行时仍需等待当前轮结束。
- 每 300 秒检查一次；同一站点请求串行，间隔随机 15–30 秒。运行超时不叠加补跑，遇限流、失效和网络错误退避。
- 每轮读取一次待办，只收 `type=homework`。为发现已提交任务和完整课程列表，另外轮转读取当前/即将开始课程的作业列表；不扫描已结束课程。
- 每页最多 50 项，每轮最多一页课程目录、两页课程作业列表及三条任务详情。课程目录六小时刷新一次。课程多时需要数轮覆盖全部，五分钟指检查周期，不保证每门课都在单轮刷新。
- 只 GET `/api/todos`、`/api/my-courses`、`/api/courses/<id>/homework-activities`、`/api/activities/<id>` 四类路径。附件只存链接，不下载。
- 不提交、撤回或编辑作业，不访问成绩、教师评语、提交文件、考试、问卷、签到或课堂录像。

接口路径参考用户提供的 [vibe-learning-in-zju](https://github.com/EviterLesRoses2/vibe-learning-in-zju)，本项目独立实现本地采集和字段白名单。登录复用现有 ZJUAM 加密表单，允许学在浙大官方 Identity CAS 中转的精确路径；密码提交始终只发送给官方 ZJUAM，站点 Cookie 只放内存，不放入爬虫数据。

## 排序与截止提醒

常规作业卡片按截止时间从晚到早排列，没有截止时间的放在最后；截止时间变化时重新排列。聊天和提醒消息保持其原有位置，六小时提醒作为新消息追加，包含课程、任务、截止时间和官方入口。已有消息会在刷新后按同样规则展示。

本机服务使用持久化最小堆，在明确截止时刻前六小时复发一次作业信息，不调用模型。首次抓到或重启时已进入最后六小时且尚未截止的，补发一次；重启和刷新不会重复派送。同一作业截止时刻改变后按新时间安排。已提交、已关闭或已截止的作业不发，只有日期或缺截止时间的不猜时刻；提交状态未知会如实展示。以上以本机最新采集状态为准，派送前再次核对本地状态，不额外访问学校。

服务需要保持运行；浏览器关闭时事件仍保存到本机，重新打开后补收。通知沿用频道静音、主动消息和安静时段设置。主动提醒在应用中显示，不等于已实现操作系统常驻通知。

## 模型与界面

作业内容直接由本机代码整理为「课程、任务、截止、状态」，详情展示本地保存的任务描述。无需 API Key，且不进入通知自动整理、聊天历史中的自动采集消息、引用转发或模型通知查询工具。作业关联的提醒同样排除在模型工具上下文之外。用户主动在聊天输入框输入的文字仍按普通聊天发送。

普通通知来源的模型设置和行为保持原样。本机服务只监听 `127.0.0.1`；采集需要访问学校服务，不需要产品方云端服务器。

## 本机验证
