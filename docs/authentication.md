# 本机身份认证

需要 Python 3.10+。在仓库目录首次安装加密依赖，再启动本机服务：

```sh
python -m pip install -r requirements.txt
python scripts/serve.py
```

也可用 `npm run dev` 启动同一个服务。打开 http://127.0.0.1:4174；服务只监听本机，同时运行 UI、认证 API 和两站持续爬虫。按 Ctrl+C 停止。

## 绑定与使用

1. 点击左下角「我 → 身份认证」、设置中的「身份认证」，或来源卡的「去认证」。
2. 在弹窗中自行输入 ZJUAM 账号密码，点击认证并绑定。等待期间保持弹窗打开；关闭或取消会撤销本次操作，不让迟到的结果绑定账号。
3. 软件直接向官方 ZJUAM 提交登录表单，确认登录成功后加密保存账号密码，并显示脱敏账号。认证失败时返回输入表单，不保存本次输入。
4. 已绑定时可重新认证或解除绑定。解绑删除本机凭据文件、清除会话；已保存通知保留。

绑定后重启服务会自动认证，不需要额外解锁密码。Cookie 只留在内存；会话失效时用已有凭据受控重认证。网络异常或限流会延后尝试；密码错误、验证码或二次验证会暂停自动尝试并显示提示。当前实现账号密码流程，额外验证需要用户处理后重新认证。

当前实现已通过离线验证，**本轮真实认证仍需用户本人在 UI 输入凭据验收**。不要在聊天中发送账号密码、Cookie 或密钥。

## 验证流程与采集边界

账号验证独立于信息来源。它不携带具体网站的 `service` 参数，也不以任何通知列表能否访问作为登录成功条件。正常流程连续执行三个请求：读取 ZJUAM 登录表单、读取 RSA 公钥、提交加密密码；随后检查 ZJUAM 返回的登录结果。认证通过后保存绑定，关闭或取消弹窗会撤销尚未完成的本次操作。

认证请求不使用爬虫的 15–30 秒间隔，也不附加网站回跳或抓取。等待来自本机网络和 ZJUAM 的响应；加密本身不会造成固定的几十秒等待。网络超时会显示重试提示，不在一次手动认证中反复提交密码。

登录表单只提交账号、RSA 加密密码、空验证码、execution 和 `_eventId=submit` 五个字段。学校返回同一 ZJUAM 主机的 HTTP CAS 表单地址或回跳时，软件会先升级为 HTTPS，再实际访问；其他目的地不跟随。重定向后只发 GET，不重复提交密码。

成功判定必须同时包含本次登录新签发、适用于 CAS 登录地址的 SSO Cookie，以及学校返回的明确登录成功证据。如果学校签发 Cookie 后返回默认门户跳转，软件改为直接读取 ZJUAM 登录页确认登录态，不访问门户；确认请求返回明确成功页面，或 CAS 接受携带该 Cookie 的请求并返回登录后跳转，才视为成功。仅有 Cookie、成功文字但没有 Cookie、普通 HTTP 200 页面都不算成功。Cookie 是否包含 `Secure` 属性不作为登录证据，认证请求始终使用 HTTPS。失败状态里的诊断只含固定阶段与原因分类，不含网址、查询值、票据或 Cookie。

绑定完成后，各受保护来源在自己的采集流程中用内存中的 ZJUAM 会话建立该站的 SSO 会话。来源访问失败、无访问权限或网页解析失败记录在来源状态中，不改变已经通过的校园账号验证结果。新增来源可接入各自的站点会话和解析规则；公开来源按原有计划采集。

## 保存位置与迁移

默认认证目录为跨平台的 `~/.pigeonpal/auth`，在仓库外；不依赖 Windows 安全目录或系统钥匙串。可指定其他仓库外目录，通知数据目录也可独立指定：

```sh
python scripts/serve.py --data-dir "D:\PigeonPal-data" --auth-dir "D:\PigeonPal-auth" 4174
```

端口是可选位置参数，默认 `4174`。默认通知目录见 [本地爬虫说明](crawling.md)。同一通知目录、认证目录只允许一个写入服务，不要同时启动独立爬虫和统一服务。

认证目录中的持久凭据文件：

| 文件 | 内容 |
| --- | --- |
| `.env` | `VERSION=1` 和 `ZJU_CREDENTIALS_ENCRYPTED`；账号密码整体经 Fernet 认证加密，不含明文或解密密钥 |
| `.auth-key` | 首次保存时生成的独立随机密钥，软件自动读取 |

迁移前停止服务，复制 `.env` 和 `.auth-key` 到另一台电脑或新目录，再用 `--auth-dir` 指向它。二者需一起复制；目标电脑安装相同运行依赖后即可自动解密并重新向学校认证。通知队列需另行复制数据目录，通知 JSON 导出不会包含认证文件。

已有凭据文件损坏、密钥缺失或不匹配时会报错，不静默覆盖；可找回原文件，或通过解除绑定后重新认证。凭据以临时文件和原子替换保存，保存失败保留上次有效绑定。

## 数据范围

凭据只提交给学校官方 ZJUAM，认证使用 HTTPS，不传给团队云端或 LLM。ZJUAM 会话及各来源会话只保存在内存，遵守 Cookie 域名、路径和有效期，并限定到相应学校主机。账号密码、Cookie 和认证票据不进入源码、通知 JSON、普通日志或浏览器 localStorage。来源卡显示真实采集状态，聊天和频道消息仍是演示内容；通知正文尚未接入消息流或 LLM。

本方案避免明文保存和误传单个密文文件；能读取 `.env` 与 `.auth-key` 两个文件的人也能解密。两个文件都应保留在个人电脑上，不加入 Git 或通知导出。

加密实现使用 [PyCA cryptography 的 Fernet](https://cryptography.io/en/latest/fernet/)，安装依赖为 `cryptography>=50.0.1,<51`。
